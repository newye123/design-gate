# 设计交付：报修工单提交页

> 这份文件是 `design_check.py` 的**合格样本**。测试要求它零问题通过。
> 它的作用不是示范"好设计"，是示范"一份能被机器验收的设计交付长什么样"——
> 每一阶段都有产物，每个产物都能被指着说"在这里"。

## 一、需求淬炼

**核心任务**：租客在 3 步内提交一条报修工单，且不需要打电话。

**用户**：
- 主用户是租客，手机上操作，通常在出问题的当口（水在漏、灯不亮），**情绪是急，不是耐心**。
- 次用户是物业客服，在后台按紧急度排队处理。
- 设备：手机为主（375–430 px 宽），弱网环境常见。

**成功标准**：
1. 提交耗时：从打开到看到「已受理」≤ 90 秒（中位数）。
2. 步骤：≤ 3 步（选类型 → 描述 → 提交），不要求注册。
3. 完成率：进入页面后提交成功 ≥ 85%。
4. 误报率：类型选错导致改派 ≤ 10%。

## 二、信息架构

**页面清单**：

| 页面 | 承载子任务 |
|---|---|
| 工单提交页 | 选类型、描述、拍照、提交 |
| 提交结果页 | 告知已受理、给工单号、给预计响应时间 |
| 我的工单列表 | 查看进度（可选入口，不阻断主路径） |

**导航结构**：单页为主，结果页不可后退到表单（避免重复提交）；列表从结果页进入。

**关键路径**：扫码/点链接 → 选类型（3 个大按钮）→ 描述（语音转写可选）→ 提交 → 结果页。

## 三、线框

```
┌─────────────────────────┐
│ 报修            [工单号] │
├─────────────────────────┤
│ 哪里出问题了？            │  ← 主区块，占 40% 高
│ [水]  [电]  [门锁]       │     三个大按钮，单手可点
├─────────────────────────┤
│ 说一句情况（可语音）      │
│ ┌─────────────────────┐ │
│ │                     │ │
│ └─────────────────────┘ │
│ [ 拍照 ]  已选 2 张      │
├─────────────────────────┤
│ [      提交报修      ]   │  ← 主按钮，固定底部
└─────────────────────────┘
```

**三态**（缺一不可）：

- **空态**：还没选类型时，描述框显示占位文案「比如：厨房水管接口在滴水，地上已有积水」，
  提交按钮禁用并说明「先选一个问题类型」。
- **加载态**：提交后按钮变成「提交中…」并锁死，防止重复点击；超过 3 秒追加一行
  「网络有点慢，正在重试」。
- **错误态**：提交失败时保留全部已填内容，给一条可操作的出路
  「没提交成功，点这里重试；也可以直接拨打 400-000-0000」。

## 四、设计系统

**颜色 token**：

| token | 值 | 用途 |
|---|---|---|
| `--ink` | `#1F2328` | 正文与标题 |
| `--ink-soft` | `#5A6470` | 次要说明 |
| `--paper` | `#FBF9F6` | 页面底色（暖白，不用纯白） |
| `--line` | `#E2DED7` | 分割线、输入框描边 |
| `--brand` | `#C2410C` | 主按钮、强调（对 `--paper` 对比度 4.9:1） |
| `--danger` | `#B42318` | 错误提示 |
| `--ok` | `#15803D` | 成功提示 |

**字体**：`"Source Han Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`。
不用 Inter（正文是中文，Inter 的中文回退会掉到系统默认，字重对不齐）。

**字号阶梯**：

| 级别 | 值 | 用在哪 |
|---|---|---|
| 大标题 | 22px / 1.3 | 页面标题 |
| 正文 | 16px / 1.6 | 说明、输入 |
| 辅助 | 14px / 1.5 | 提示、工单号 |
| 极小 | 12px / 1.4 | 仅用于页脚法务文字 |

**间距刻度**：4 / 8 / 12 / 16 / 24 / 32 px。圆角 10px（按钮）、14px（卡片）。
主按钮最小点击区 48×48 px。

**组件**：主按钮（默认/按下/禁用/加载中）、输入框（默认/聚焦/错误）、类型选择块（未选/已选）。

## 五、对抗审查

1. **核心任务真的三步内完成吗？** 选类型 → 描述 → 提交，是三步。但"描述"如果要求必填
   20 字以上，实际会卡住。改法：描述最少 4 字即可提交，客服可回电补充。
2. **哪个假设没被验证？** 假设"租客愿意拍照"。老人可能不会。改法：拍照非必填，
   并在空态文案里给"不拍也能提交"的明确提示。
3. **三态真的处理了吗？** 空态、加载态、错误态都画了。但**断网**这一态没画——
   弱网是主场景，需要单独一版：离线时草稿本地留存，恢复后提示"有一条未提交的报修"。
4. **窄屏会不会崩？** 375 px 下三个类型按钮横排每个只有 108 px，中文两个字够，
   但"门锁"加图标会挤。改法：≤ 380 px 时改成两列，第三个跨行。
5. **有没有为了好看牺牲可用？** 主按钮用了品牌橙，对比度 4.9:1 达标；但禁用态如果只降透明度，
   在阳光下会看不见。改法：禁用态同时降透明度并改文案。

**改单（按优先级）**：

| 优先级 | 改什么 | 为什么 |
|---|---|---|
| P0 | 描述改为最少 4 字 | 直接决定完成率 |
| P0 | 补断网态 | 弱网是主场景 |
| P1 | ≤380px 类型按钮两列 | 窄屏会挤 |
| P1 | 禁用态不只靠透明度 | 户外可读性 |
| P2 | 拍照非必填文案前置 | 降低老人门槛 |
